## 1. Official source and access evidence

- NESDC 16-sector 2021 I/O [download listing](https://www.nesdc.go.th/download/i-o-2021-16-sectors/) lists Excel.
- Its public redirect [download entry](https://www.nesdc.go.th/?p=1543&ddl=1544) resolves to [DataIO2021x16.xlsx](https://www.nesdc.go.th/wp-content/uploads/2025/03/DataIO2021x16.xlsx).
- Page date shown on Thai listing: 25 February 2025, while observation/data year is 2021. They are not interchangeable.
- Text-oriented web extraction could follow the redirect but only returned undecodable binary-like content for the XLSX.
- Direct network download in the model's computation container failed DNS resolution and a separate container-download attempt did not materialize bytes.
- A targeted, read-only interactive web-browser check confirmed the NESDC Excel link but the redirected file did not become an openable cell grid. No real worksheet names or matrix data were produced.
- A public third-party viewer did not provide verifiable cell readback.

**Stop-rule:** no original downloadable XLSX bytes means NO real-file SHA256, NO original sheet/range provenance, NO 16 named source sectors, NO unit/valuation verification and NO 16+16 independent official controls. Therefore IO_2021_MATRIX_STATUS = DATA_BLOCKED and verified official intermediate-flow cells = **0 / 256**.

This is a limitation of currently accessible source bytes, NOT a claim that NESDC data do not exist, nor a request to invent them from another dataset.

## 2. Functional validation delivered

The standalone schema/arithmetic validator executed **86/86 checks PASS**. These are synthetic and adversarial checks of a general 16x16 data acceptance gate, not verification of the original NESDC figures.

Coverage included:

- Exact official source URL, 2021 observation period, original source SHA256 and byte count, XLSX ZIP/worksheet integrity, no anonymous copied values.
- Required unique row/column sector labels, cell provenance and exact 16x16 coordinates.
- Explicit intermediate-transaction measurement, THB unit and valuation basis, without assuming purchaser/basic/producer price in advance.
- Retaining justified negative entries, and blocking null, blank, NA, dash, nonnumeric and nonfinite entries rather than silently replacing them with zeros.
- Original published row and column controls from distinct cell addresses with matched measurement definitions. Rejecting self-derived mock controls as official.
- A deliberate one-cell change detected via both its affected row and affected column; tamper tests repeated for all 16 rows and 16 columns.
- Missing 16th row/column, double-used source control addresses, duplicate sector labels, source year mismatch, unjustified rounding tolerance, fake hash and post-2021 data substitution blocked.
- A mathematically correct **synthetic** 256-cell grid classified as SYNTHETIC_ARITHMETIC_FIXTURE_PASS_NOT_OFFICIAL. Zero real source cells promoted by such a passing fixture.
- No numeric Thailand automation forecast or policy certificate derived.

The committed validator returns a **PENDING_SOURCE_VERIFICATION** class even when a user-provided JSON object has plausible source-looking fields. A string such as an SHA256 or an attest-checked Boolean is not equivalent to the original NESDC XLSX archive being cryptographically checked.

## 3. XLSX archive/worksheet-inspector smoke test

A small Node.js 18+ standard-library inspector was created (no npm package, no network access) with:
- ZIP central directory reading, archive entry bounds, compressed-size checks and CRC32;
- original file SHA256;
- workbook relationship resolution and XML namespace-compatible sheet inspection;
- nonempty worksheet cell addresses, shared strings, signed numbers, cached formulas and cell types;
- optional full JSON readback for later selection of a source-backed block, but no automatic guessing of a 16-sector range.

A **separately generated synthetic XLSX**, created using artifact_tool and never represented as official data, yielded:
- 1 synthetic worksheet named SOURCE_MOCK_ONLY;
- 324 nonempty cells;
- 288 cached numeric values including 16x16 synthetic entries and 32 source-control SUM formula values;
- 32 formulas read back with source cell addresses;
- the deliberately negative synthetic adjustment remained negative;
- a valid ZIP CRC and deterministic SHA256;
- after one byte was maliciously altered in the mock XLSX, the reader returned ZIP_CRC_SIZE_MISMATCH and did NOT silently accept the file.

The tested offline inspector uses the same archive/XML approach as the committed script. The committed script was syntax-validated before write, but a separate Node CLI execution of the **exact GitHub-committed bytes** was not claimed. It should be run against the actual NESDC file when that file becomes available.

These mock tests prove only that the generic reading method works for the supported XML/ZIP constructs. Some official Excel files may contain additional features or formulas that require further inspection.

## 5. Why actual numerical modeling is still blocked

The source workbook could be:
- a matrix with price basis different from what an analyst expects;
- a table containing intermediate flows, imports, value added and final demand in separate ranges;
- a source whose 16 published totals are gross output rather than row sums over the 16x16 intermediate transactions.

Selecting the first available 256 numbers would be an epistemic error. A valid historical input coefficient cannot be computed until the cell block and independently published totals have been inspected, units checked and domestic/import distinctions understood. Even genuine 2021 coefficients alone do not establish how industries operate after an unknown future full-automation milestone.
